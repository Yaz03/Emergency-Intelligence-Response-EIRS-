Problem Statement
The Emergency Data Gap
⏱️

Critical Golden Hour

First responders often lack patient medical history during the crucial first minutes of an emergency, leading to uninformed treatment decisions.

🗂️

No Portable Medical Records

Patients carry no standardised, instantly accessible record of allergies, medications, or blood type that a paramedic can read on-site.

📡

No Real-time Dispatch Insight

Administrators have no live visibility into incident density, response time trends, or high-risk geographic areas.

📋

Manual Incident Logging

Paper-based or phone-call incident reporting leads to data loss, delays, and zero analytics capability for future planning.

Security
Security Architecture
  • 🔒

    Row Level Security (RLS)

    Every Supabase table enforces RLS. Patients can only read/write their own profile. Paramedics can only read incidents assigned to them.

  • 🔑

    Encrypted QR Tokens

    QR codes embed an AES-encrypted patient ID with a time-limited expiry stored in emergency_tokens. Expired tokens are rejected.

  • 🛡️

    Role-Gated Web Portal

    login.html and admin_login.html verify user role from user_roles table before granting access. Wrong role → access denied.

  • 💾

    Secure Token Storage

    Auth tokens in the Flutter app are stored using flutter_secure_storage (Keychain on iOS, EncryptedSharedPreferences on Android).

Patient taps SOS button in Flutter app
→
📍 GPS coordinates captured via geolocator
→
🏙️ Coordinates reverse-geocoded to city/address via geocoding package
→
📲 SMS sent to both emergency contacts with location link
→
📋 Incident record created in Supabase with GPS, time, and patient ID
→
📊 Incident appears in paramedic dashboard + admin analytics
